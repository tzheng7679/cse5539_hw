\section*{Problem 1}

In MHA, the equations would be \begin{gather*}
    MHA_i = \softmax(\frac{Q_iK_i^T}{\sqrt{d_k/h}})V_i \\
    MHA = \Linear([MHA_1, MHA_2, ..., MHA_h])
\end{gather*}

where $i$ represents this being for the $i$-th head, and $Q_i = W_{q,i}x$, $K_i = W_{K,i}x$, and $V_i = W_{v,i}x$ represents the query, key, and values matrices, respectively, for the head. $Q_i, K_i, V_i \in \mathbb{R}^{n, d_k/h}$, where $n$ is the length of the sequence,
$d_k$ is the dimension of the hidden state of the model (so the dimension of each column of $x$).

The query matrix comprises query vectors corresponding to each token. MHA then takes the dot product between each token's query vector and the key vectors of all previous tokens and itself and softmaxes those dot products (which are scaled before the softmax in the case of MHA by $\sqrt{d_k}$).
These scores are then taken to weigh how much to use the value vector for each of the preceding tokens and itself, and the sum of those weighed value vectors are added to the embedding of each token. This is the output of one head of attention; the outputs of all the heads in a layer are then concatenated and projected through a linear layer for the final output of SDPA.

\subsection*{2.1}
The minimum possible would be $1$, since \begin{gather*}
    p(w_i) \leq 1 \\
    \implies \log_2 p(w_i|...) \leq 0 \\
    \implies H = -\frac{1}{n}\sum_{i=1}^n \log_2p(w_i|...) \geq 0 \\
    \implies \ppl(w) = 2^H \geq 2^0 = 1
\end{gather*}

Then there would be no finite maximum, since $p(w_i|...)$ can be 0, in which case $\log_2 p(w_i|...) \rightarrow -\infty \implies H \rightarrow \infty \implies ppl(w) \rightarrow \infty$.

\subsection*{3.1}

Because the gradient is the direction of steepest ascent on the loss function with respect to the parameters. That means that stepping the parameters in the direction of the gradient (for some step size) leads to an increase in the loss function.

In SGD, you change the parameters by adding $-\gamma g_t$. $g_t$ is the sum of a momentum term and the gradient with the sign flipped when $maximize$ is true. That means when $maximize$ is true, you move the parameters in the direction opposite to the negative gradient, or just in the direction of the gradient, which is the direction of steepest ascent. In that case, that would mean maximizing your objective function. Then when $maximize$ is false, the parameters are updated in the opposite direction, minimizing your objective.

\section*{Problem 5}

\subsection*{5.1}

The prefill phase is where you fill the KV cache with the calculated key and value vector values for all the prompt tokens. The decode phase is where you generate new tokens from the existing ones, and add to the KV cache as you generate each token (i.e. add the key and value vector values for one token at a time). 

They are fundamentally different in that the prefill phase computes all these attention scores and looks up the key and value vectors together (and needs to use the query vector for all tokens), whereas the decode phase only computes these for one token relative to all the others, and uses only the query vectors for one token. This means that the prefill phase is more dependent on compute to fill the KV cache, whereas decoding is dependent on memory bandwidth to read from the KV cache.

The inefficient part would be the decoding phase, since you need to read from the KV cache for the forward pass and can't parallelize operations well (you can parallelize calculations in the prefill phase, but in the decode phase you need to wait for the pass through each layer to generate anything).

One idea used in practice is chunked prefill, where longer input prompts are split into chunks and then the processor alternates between prefilling over these chunks and decoding for other requests. This means that you are balancing memory utilization and compute intensity.


\subsection*{5.2}

Because you need to store the key and value vectors for each token; with every token you add to the sequence, you add another set of key and value vectors to the KV cache. Since the size of memory is constant for each token, the size of the cache is linear with the number of tokens (i.e. sequence length).

One way to reduce memory cost would be to use lower precision weights; this would mean that the cache used by each token would be smaller, which would reduce total memory and bandwidth usage. The trade-offs of this would be potentially include reduced accuracy and potential numerical errors during training (such as underflow or overflow).
